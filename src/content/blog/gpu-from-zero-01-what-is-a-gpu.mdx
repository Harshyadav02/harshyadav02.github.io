## About this series

If you work with Kubernetes, there's a good chance you have already deployed something on a GPU node. You add `nvidia.com/gpu: 1` to the pod spec, the pod lands on a GPU machine, and it works. But what is actually happening underneath is often unclear.

**GPU from Zero** is a series that explains GPUs step by step, starting from the very basics. Each part covers one idea, uses plain language, and builds on the previous part. Later parts include hands-on labs where we deliberately break things, read the errors, and fix them.

No previous GPU knowledge is needed.

**In this part, you will learn:**

- What a GPU is and how it differs from a CPU
- Why AI and machine learning run on GPUs
- What GPU memory (VRAM) is, and why it's the most important number on a GPU
- How to estimate whether an AI model will fit on a GPU

## CPU vs GPU

Every computer has a **CPU** (Central Processing Unit). It's the main processor that runs the operating system and your applications. A CPU has a small number of powerful **cores**. A core is a unit that can execute instructions independently. A typical server CPU has between 8 and 64 cores.

Each CPU core is fast and flexible. It's good at work that involves many different steps and decisions, such as handling a web request, reading a file, or running business logic.

A **GPU** (Graphics Processing Unit) takes a different approach. Instead of a few powerful cores, it has **thousands of small, simple cores**. Each one is much weaker than a CPU core, but they all work at the same time, each on a different piece of data.

### A simple analogy

Imagine you need to grade 10,000 exam papers using the same answer key.

- **The CPU approach:** one experienced professor grades every paper, one after another. Each paper is graded quickly and correctly, but the whole job takes a long time.
- **The GPU approach:** 1,000 students each grade 10 papers at the same time. Each student is slower than the professor, but the whole job is done in minutes.

This is the key idea:

> A GPU is fast when there is **a large amount of the same simple work** that can be done in parallel.

For varied, step-by-step work, a CPU is still the better tool. That's why every GPU server also has a CPU. The CPU runs the program and hands the heavy, repetitive calculations to the GPU.

## Why AI runs on GPUs

GPUs were originally designed for graphics. A Full HD screen has about 2 million pixels, and the screen is redrawn around 60 times per second. Every pixel needs a similar calculation, which is a perfect fit for thousands of cores working in parallel.

AI models turned out to need the same kind of work. Under the hood, an AI model is mostly a very large collection of numbers, and running or training it means multiplying large tables of numbers (called **matrices**) again and again. This is the same "large amount of simple, repeated work" that GPUs are built for.

To give a sense of scale, the **NVIDIA T4**, the GPU in AWS `g4dn` instances, has:

- **2,560 CUDA cores**, used for general parallel calculations
- **320 Tensor Cores**, special units designed specifically for the matrix multiplications used in AI

## GPU memory (VRAM)

This is the most important concept in this part.

A GPU has its own dedicated memory, called **VRAM** (Video RAM). It's separate from the computer's main memory (RAM). The GPU can only work on data that is stored in its own VRAM.

So before a GPU can do anything, the data must be copied from RAM into VRAM:

1. The program loads the AI model and input data into normal RAM.
2. The data is copied to the GPU's VRAM over a connection called **PCIe**.
3. The GPU performs the calculations using the data in VRAM.

This leads to the most common GPU problem you'll run into: **the model doesn't fit in VRAM**. When that happens, the program fails with an error like this:

```text
torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 2.00 GiB.
```

Unlike RAM on a normal server, VRAM can't be extended with swap space. If the model doesn't fit, it won't run.

### How to estimate whether a model fits

AI model sizes are described by their number of **parameters**, the numbers the model has learned. For example, a "7B" model has 7 billion parameters.

Each parameter takes up some memory. The most common format for running models, called **FP16** (16-bit floating point), uses **2 bytes per parameter**. That gives a simple rule of thumb:

```text
memory needed = number of parameters × bytes per parameter
```

| Model size | Calculation | Memory needed | Fits on a T4 (16 GB)? |
|---|---|---|---|
| 7 billion parameters | 7 × 2 | 14 GB | Yes, just about |
| 13 billion parameters | 13 × 2 | 26 GB | No |

This only covers the model itself. A running model also needs extra memory for the data it is processing, so in practice you need some headroom beyond this number. We'll measure this in a later part.

### Common GPUs on AWS

| EC2 instance family | GPU | VRAM per GPU |

| `g4dn` | NVIDIA T4 | 16 GB |
| `g5` | NVIDIA A10G | 24 GB |
| `p4d` | NVIDIA A100 | 40 GB (8 GPUs per instance) |

## Connecting this to Kubernetes

When a pod requests a GPU like this:

```yaml
resources:
  limits:
    nvidia.com/gpu: 1
```

Kubernetes schedules the pod onto a node that has an available GPU and gives the pod **one entire GPU**, including all of its VRAM. By default, a GPU isn't shared between pods. Later parts of this series explain how that works and how GPUs can be shared.

## Key terms

| Term | Meaning |
|---|---|
| CPU | The main processor. A few powerful cores, good at varied tasks |
| GPU | A processor with thousands of simple cores, good at parallel tasks |
| Core | A unit inside a processor that executes instructions |
| VRAM | The GPU's own memory. Models and data must fit here |
| CUDA | NVIDIA's platform that lets software run calculations on the GPU |
| Driver | Software that lets the operating system communicate with the GPU |
| Parameter | One of the numbers an AI model has learned. "7B" means 7 billion |
| FP16 | A number format that uses 2 bytes per value, common for running models |

## Key takeaways

- A CPU has a few powerful cores. A GPU has thousands of simple cores working in parallel.
- GPUs are fast for large amounts of repetitive work, which is exactly what AI models need.
- The GPU can only use data stored in its own memory, VRAM.
- If a model doesn't fit in VRAM, it fails with a "CUDA out of memory" error.
- Quick estimate: parameters × 2 bytes (FP16) = memory needed for the model.

## Try it yourself

You don't need your own GPU to follow along. Google Colab provides a free NVIDIA T4:

1. Open [colab.research.google.com](https://colab.research.google.com) and create a new notebook.
2. Select **Runtime → Change runtime type**, choose **T4 GPU**, and click **Save**.
3. Type `!nvidia-smi` in a cell and press **Shift + Enter**.

You'll see a table with details about the GPU. In Part 2, we go through that output line by line.
